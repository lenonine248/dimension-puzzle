# 次元圧縮パズル

2Dと3Dを自由に行き来し、次元を切り替えると世界が（不可逆に）再構成されるブロックパズル。
3Dで畳む向きを選んで2Dに圧縮し、2Dで数字（奥行き）を操作してから再構成する、という往復で解く。

## 構成

```
dimension-puzzle/
├─ index.html            … ゲーム本体（単一HTML・エンジン/ソルバー/エディタを内包）
├─ stages.js             … 本番同梱用のステージ束（build_stages.py が生成）
├─ build_stages.py       … stages/*.json から stages.js と manifest.json を生成
├─ dimension_puzzle_spec.md … 設計仕様（ゲーム全体）
├─ solver_spec.md        … ソルバー機能の仕様
├─ stages/
│  ├─ manifest.json      … 開発時 fetch 用のステージ一覧
│  ├─ tiers.json         … 章番号→章名
│  └─ stageXXYY.json     … ステージ（1ファイル1ステージ／XX=章, YY=章内番号）
├─ package.json          … テスト実行用スクリプト
└─ dev-tests/            … 開発用テスト・ツール（配布不要）
   ├─ _helper.js         … テスト共通ヘルパー
   ├─ solver_test.js     … ソルバー検証＋全ステージが解けることの確認
   ├─ score_test.js      … 星評価・par・ヒント探索の検証
   ├─ page_smoke_test.js … ページ起動スモーク（要 jsdom）
   ├─ hint_visual_test.js… ヒント表示の状態遷移（要 jsdom）
   └─ compute_pars.js    … 全ステージの par を計算してJSONへ焼き込むツール
```

全14章・47ステージ。第1〜7章がチュートリアル、第8〜14章が本編。

## 公開・実行

- **公開（GitHub Pages 等）**: フォルダごと配置すれば `index.html` が `stages.js` を読み込んで動く。
- **ローカルで開発**: ローカルサーバを立て、`index.html?dev` を開くと `stages/` フォルダから直接読み込む（ビルド不要で即反映）。
  ```
  python3 -m http.server
  # → http://localhost:8000/index.html?dev
  ```
- `stages.js` も `stages/` も読めない場合は内蔵デモにフォールバックする。

## ステージの追加・編集

1. ゲーム画面の「エディタ」ボタンでエディタを開く（配置・重力・スライス編集・3D/4方向プレビュー）。
2. 「JSON書き出し」でステージJSONをダウンロードし、`stages/` に置く。
3. 反映:
   - 開発中: `stages/manifest.json` にファイル名を加え、`index.html?dev` で確認。
   - 公開前: `python3 build_stages.py` を実行して `stages.js` と `manifest.json` を更新。

### ステージJSON形式

```json
{
  "schema": 1,
  "id": "stage01",
  "name": "はじまり",
  "tier": 1,
  "order": 1,
  "dims": { "W": 4, "H": 3, "D": 4 },
  "voxels": [ [x, y, z, "ground", false], [0,1,3,"avatar",true] ]
}
```

- `voxels` は `[x, y, z, type, gravity]` の配列（押せるブロックは末尾に連結グループ番号を足して `[x, y, z, "push", gravity, group]` も可）。
- `type` は `ground` / `push` / `goal` / `hazard` / `avatar`。
- `avatar` は常に重力あり。
- `group`（省略可）は押せるブロックの連結指定。同じ `group` 番号の押せるブロックは1つの塊として一緒に押される。省略した押せるブロックは、隣接する省略ブロック同士が従来どおり自動連結される（互換）。エディタの「連結ツール」で編集できる。
- `foldAllow`（省略可、既定は全方向許可）はプレイ中に選べる畳む向きの制限。`{"+x":false}` のように不許可の向きだけを `false` で指定する。不許可の向きは3D画面の床の矢印が非表示になり選択できなくなる。**全方向を `false` にすると、そのステージは一切2Dへ圧縮できない3D専用パズルになる**（次元切り替えボタン／Spaceキーは無効化され、読み上げ表示に「圧縮不可（3D専用ステージ）」と出る）。
- `swapAllow`（省略可、既定は `true`）を `false` にすると、2D画面での数字入れ替え操作（アバターのクリック選択・隣接セルとの交換）ができなくなる（見た目・レイアウトは変わらない）。
- `walls`（省略可、既定は `true`＝壁あり）を `false` にすると、ステージの周囲・天井（x/zの境界、および高さYの上限）に壁が無くなる。壁が無い方向へ歩く・押す・登るのは（配置されたブロックが無いのと同じ扱いで）妨げられず、その先で支えが無ければY=0の穴に落ちるのと同じように落下・消滅する。3D画面ではステージの外側にも縁と霧が表示され、危険ハイライトも境界の外へ働く。2Dの立面表示は見た目を変えていない（危険ハイライトで対応）。
- どちらもエディタの操作バー（「畳む向き」チェックボックス4つ・「数字入れ替え可」チェックボックス・「周囲・天井に壁あり」チェックボックス）で編集できる。既定値（全許可・入替可・壁あり）のときはJSONに出力されない（省略＝互換）。
- `par`（省略可、整数）はソルバーが求めた最短手数。クリア時の星評価の基準に使う。手で書かず `npm run pars`（= `node dev-tests/compute_pars.js`）で一括計算・焼き込みする。**盤面を変更したら再計算すること。**

## 操作

**3D**: ドラッグ＝回転／ホイール＝ズーム／WASD・カーソル＝アバターが歩く。修飾なしは登る専用（障害物・押せるブロック・他のアバターの上に1段登る、押さない）。Shiftを押しながら移動すると押す専用になり、目の前の押せるブロックを押す。押せない場合は登る・歩くにフォールバックし、それもできなければ何もしない。床の矢印＝畳む向き（クリックで固定・再クリックで解除、C＝カメラ追従）／Space＝2Dへ圧縮。

**2D**: ←/→＝登る（Shift+←/→＝押す、押せなければ登る・歩くにフォールバック）／アバターをクリックして選び隣接セルをクリック＝数字入れ替え（1手1入れ替え）／Space＝3Dへ再構成。

共通: ゴール到達でクリア、アバター全滅・ゴール消滅でやり直し。U＝ひとつ戻す、R＝リセット。🔊ボタン＝サウンド切替。「オプション」でサウンド・音量・アニメーション演出・画面の揺れを個別に設定できる（設定はブラウザに保存）。音はWeb Audioで合成し、音声ファイルは使わない。

## スコア・ヒント・記録

- **手数と星**: 歩く/登る/押す/畳む/展開/数字入れ替えを各1手として数える（何も起きなかった入力は数えず、アンドゥ履歴にも残さない）。クリア時に **★3＝par以内 / ★2＝par+max(2,ceil(par×0.5))以内 / ★1＝クリア** を判定。星は手数のみで決まり、「アンドゥなし」「ヒントなし」は別の実績バッジとして記録する。
- **次の一手ヒント**: ツールバーの「次の一手」で、現在の盤面（2Dの途中でも可）からソルバーが最短解を計算し、**最初の1手だけ**を盤面上に視覚表示する（進行方向の矢印＋押す対象のハイライト＋操作キーのタグ、畳む場合は該当ギズモの発光）。矢印はワールド座標に描くのでカメラを回しても正しい。**盤面が変化するまで表示が持続**する。解けない場合・探索打ち切りの場合のみテキストで案内する。
- **記録**: タイトルの「記録」から累計統計（クリア数・星合計・各バッジ数・総手数・折り/展開/押し/入替/アンドゥ/ヒント回数・「消失点に消えたもの」）を閲覧できる。進行と統計は `localStorage`（`dp_progress` / `dp_stats`）に保存。

## 開発者モード・ソルバー

- コンソールで `dp.dev(1)` を実行すると開発者モードになり、タイトルに「エディタ」が出る（`dp.dev(0)` で解除）。
- エディタには**ソルバーパネル**がある。「解を探す」（可否・par・解パス）、「設計チェック」（**折らずに解けてしまうリークの検出**・想定解との近道比較・任意で詰み検出）、「解を再生」（実UI関数で1手ずつ再生）、「想定解の記録」（テストプレイした手順をparの比較基準として記録）。
- 数字入れ替え(swap)を探索に含めるか、詰み検出を行うかは**既定オフの任意オプション**。swapオフで解が出ない場合は「解なし（swapを除く探索）」と表示され、「解けない」と混同しないようになっている。探索は状態数・時間の上限で打ち切られ、その場合は「解なし」ではなく「未確定」を返す。

## テスト

ロジックはNode上で自動テストする。`dev-tests/` を参照。

```
npm test          # ロジック層（DOM不要・高速）: ソルバー + スコア
npm run test:page # ページ起動層（要 npm i）: 起動スモーク + ヒント状態遷移
npm run test:all  # 全部
```

その他のコマンド:

```
npm run build   # stages/*.json → stages.js（= python3 build_stages.py）
npm run pars    # 全ステージの par を再計算してJSONへ焼き込む
npm run serve   # ローカルサーバ（http://localhost:8000/index.html?dev）
```

ページ起動層のテストは、ロジック層では拾えない**初期化エラーやボタン未配線**を検出するためにある（実際にこの種の不具合が発生した経緯があるため、UIに手を入れたら必ず通すこと）。
